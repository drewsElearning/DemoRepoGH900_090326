01

What Git remembers

Git is a distributed version control system. It records a project as snapshots, so you can inspect what changed, compare versions, and recover from mistakes without passing files around.

02

Repositories & working trees

A repository contains your project files plus the hidden .git database. Your working tree is what you are editing now; git status shows how it differs from the last commit.

03

Stage a meaningful change

Staging is a deliberate review boundary. Use git add to choose exactly what belongs in the next snapshot, then use git diff --staged to inspect that snapshot before you create it.

04

Commit the snapshot

git commit -m "..." records the staged change with an author, timestamp, and message. Prefer small commits that explain one intent and leave the project in a usable state.

05

Branch to explore

A branch is a movable pointer to a commit, not a second copy of the project. Create a focused line of work with git switch -c feature/name, then return to another branch without losing your progress.

06

Merge with context

When a branch is ready, compare it with the target branch, resolve any conflicts carefully, and merge it. A conflict is Git asking you to make an explicit choice, not a failure of the repository.

07

Share through remotes

A remote is a named connection to another copy of the repository. git push shares local commits; git pull brings remote commits down so your branch can catch up.

08

A reliable daily loop

Inspect, make one change, review the diff, stage intentionally, commit clearly, and share through a branch. This loop turns version control into a calm record of decisions.
